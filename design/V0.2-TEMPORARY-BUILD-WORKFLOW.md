# SubhForge v0.2 Temporary Cost-Controlled Build Workflow

**Status:** Accepted for pre-code and v0.2 construction  
**Decision date:** 2026-10-04  
**Scope:** Temporary developer workflow only; not SubhForge product architecture

## Outcome

The workflow is executable with the subscriptions and tools already available. No new subscription, Claude Max plan, Kilo credit purchase, or enterprise-style provider redundancy is required.

The operating ceiling is **$50 per month before tax**:

| Cost class | Limit |
|---|---:|
| Existing ChatGPT subscription | $20/month |
| Existing Claude Pro subscription | $20/month |
| New variable DeepSeek spend | maximum $10/month |
| Kilo credits | $0 planned |
| Anthropic API spend | $0 planned |

DeepSeek uses the existing prepaid provider balance first. Auto-recharge remains disabled.

## Responsibilities and escalation

| Stage | Default tool/model | Boundary |
|---|---|---|
| Routine implementation, tests, focused fixes and deterministic debugging | VS Code + Kilo + DeepSeek Flash through BYOK | Code and synthetic/test data only. Start with a fresh bounded task and specific files. One repair retry, then stop and escalate. |
| Architecture, requirements, scope control and difficult reasoning | ChatGPT subscription plus Claude Code + Claude Pro | ChatGPT leads bounded analysis and synthesis. Claude is a co-architect for material architecture decisions—not only a reviewer—and develops alternative options/trade-offs from a bounded packet. Use Sonnet normally and Opus only for high-risk/critical architecture. Both remain advisory; subscription limits are hard stops. |
| Independent architecture challenge and high-value review | Claude Code + Claude Pro; Sonnet normally, Opus only for exceptional/high-risk work | Use a fresh bounded, read-only, structured handoff that does not receive the primary hidden reasoning transcript. Findings and alternative designs are evidence, never authority. No automatic Anthropic API spend. |
| Final decision | Subhadeep | Provider/model output cannot approve architecture or expand scope on its own. |

Escalation order:

1. Use deterministic tools before a model where they can answer the question.
2. Use DeepSeek for routine implementation/test work.
3. Use ChatGPT for primary architecture, requirements, scope and difficult synthesis.
4. Add Claude Sonnet as a bounded independent co-architect/reviewer for material architecture decisions; use Opus only when risk/complexity justifies the scarcer allowance. One fresh handoff should normally produce Claude's alternative options/trade-offs/recommendation and challenge the ChatGPT-led analysis—do not spend a second Claude call by default.
5. Stop for Subhadeep when a consequential decision, disagreement, repeated failure, or budget boundary is reached.

There is no automatic provider fallback. A limit, authentication error, exhausted balance, repeated equivalent failure, or denied permission must surface as a stop or explicit escalation.

## Temporary operator controls

- Keep Kilo as the familiar execution shell.
- Begin each substantive task with narrow scope, named files and a clear acceptance condition.
- Prefer deterministic tests and repository evidence over repeated model calls.
- Permit at most one repair retry for the same failure before stopping or escalating.
- Keep destructive shell commands denied and edits/unknown shell commands approval-gated.
- Keep unused MCP servers and broad tool access disabled.
- Do not use Kilo auto/frontier routing, purchased Kilo credits, Claude Max, or automatic paid fallback as normal continuity mechanisms.
- Record material provider/model usage where practical; an unavailable exact historical task delta is recorded as unavailable rather than estimated.

## Architecture-isolation confirmation

This workflow is construction scaffolding. It does not change SubhForge lifecycle semantics, authority, work state, persistence, verification, or provider abstraction.

In particular:

- SubhForge v0.2 currently runs through Kilo as its primary execution harness. Kilo is therefore required for the planned v0.2 runtime path, but it does not define SubhForge lifecycle semantics or own product authority. ChatGPT OAuth, DeepSeek, Claude Code, Claude Pro, and external construction skills remain replaceable worker/tool choices rather than mandatory product-runtime components.
- No subscription state, provider token, Kilo session, chat history, or provider-specific usage record becomes product authority.
- Durable product decisions are promoted to their existing normative documents and Git artifacts.
- Temporary review tooling follows the removal boundary in [V0.2-ARCHITECTURE-REVIEW-TOOLING.md](V0.2-ARCHITECTURE-REVIEW-TOOLING.md#10-temporary-lifecycle-and-removal).
- Product architecture continues to treat models and harnesses as replaceable workers behind bounded interfaces.

Therefore, closing pre-code checklist Item 2 records an executable operator workflow; it does not add a SubhForge runtime component.

## Re-verification rule

Do not repeat these proofs merely to close the checklist. Re-run only the smallest affected proof when:

- authentication or provider routing is reconfigured;
- a Kilo or provider change may have altered billing, fallback, permission, or hard-stop behavior;
- the existing evidence becomes unavailable or contradicted; or
- a later release gate explicitly requires a current live canary.

Otherwise, reuse the durable evidence and preserve budget.
