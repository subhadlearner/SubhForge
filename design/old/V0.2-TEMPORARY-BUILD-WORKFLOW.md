# SubhForge v0.2 Temporary Cost-Controlled Build Workflow

**Status:** Accepted for pre-code and v0.2 construction  
**Decision date:** 2026-10-04  
**Last reconciled:** 2026-10-06  
**Scope:** Temporary developer workflow only; not SubhForge product architecture or runtime authority

## Outcome

The workflow is executable with the subscriptions and tools already available. No new subscription, Claude Max plan, Kilo credit purchase, or enterprise-style provider redundancy is required for the current construction plan.

This document describes **current cost-controlled execution choices**, not permanent model/harness assignments. The active PRD/Architecture require model/provider/harness adaptability.

The operating ceiling is **$50 per month before tax**:

| Cost class | Limit |
|---|---:|
| Existing ChatGPT subscription | $20/month |
| Existing Claude Pro subscription | $20/month |
| New variable DeepSeek spend | maximum $10/month |
| Kilo credits | $0 planned |
| Anthropic API spend | $0 planned |

DeepSeek uses the existing prepaid provider balance first. Auto-recharge remains disabled.

## Responsibilities and escalation

| Stage | Current default tool/model | Boundary |
|---|---|---|
| Routine implementation, tests, focused fixes and deterministic debugging | VS Code + current execution harness + DeepSeek through BYOK | Code and synthetic/test data only. Start with a fresh bounded task and specific files. One repair retry, then stop and escalate. |
| Product/requirements, architecture, scope control and difficult synthesis | ChatGPT subscription as primary reasoning path plus Claude Code + Claude Pro for material independent co-architecture/challenge | Agent responsibility and authority come from SubhForge contracts, not the chosen model. Use Claude Sonnet normally for material co-architecture; Opus only for explicit high-risk/critical escalation. Subscription limits are hard stops. |
| Independent architecture challenge and selected hard review/diagnosis | Claude Code + Claude Pro; Sonnet normally, Opus only for exceptional/high-risk work | Use a fresh bounded, read-only, structured handoff that does not receive the primary hidden reasoning transcript. Findings and alternative designs are evidence, never authority. No automatic Anthropic API spend. |
| Mechanical state/graph/validation work | Deterministic repository tooling first | Do not pay a model to decide what local code can prove reliably. |
| Final consequential decision | Subhadeep | Provider/model output cannot approve product/architecture authority, waive risk, or expand scope on its own. |

Escalation order:

1. Use deterministic tools before a model where they can answer the question.
2. Use DeepSeek for routine implementation/test work while it remains the economical configured worker.
3. Use the primary strong reasoning path (currently ChatGPT subscription) for requirements, architecture, scope and difficult synthesis.
4. Add Claude Sonnet as a bounded independent co-architect/reviewer for material architecture decisions; use Opus only when risk/complexity justifies the scarcer allowance. One fresh handoff should normally produce Claude's alternative options/trade-offs/recommendation and challenge the primary analysis—do not spend a second Claude call by default.
5. Stop for Subhadeep when a consequential decision, disagreement, repeated failure, provider-limit condition or budget boundary is reached.

Changing the configured model/provider later does **not** change this authority/escalation shape.

There is no automatic provider fallback. A limit, authentication error, exhausted balance, repeated equivalent failure, or denied permission must surface as a stop or explicit escalation.

## Temporary operator controls

- Use Kilo as the current familiar execution shell where it remains useful; do not let construction convenience become a permanent product dependency.
- Begin each substantive task with narrow scope, named files and a clear acceptance condition.
- Prefer deterministic tests and repository evidence over repeated model calls.
- Permit at most one repair retry for the same failure before stopping or escalating.
- Keep destructive shell commands denied and edits/unknown shell commands approval-gated.
- Keep unused MCP servers and broad tool access disabled.
- Do not use Kilo auto/frontier routing, purchased Kilo credits, Claude Max, or automatic paid fallback as normal continuity mechanisms.
- Record material provider/model usage where practical; an unavailable exact historical task delta is recorded as unavailable rather than estimated.

## Architecture-isolation confirmation

This workflow is construction scaffolding. It does not change SubhForge lifecycle semantics, authority, work state, persistence, verification, handover meaning, or provider/harness boundaries.

In particular:

- Kilo is the **current** familiar execution harness, not a permanent SubhForge semantic/runtime dependency. The active Architecture requires migration-friendly seams so a future harness change does not rewrite project history or workflow meaning.
- ChatGPT, DeepSeek, Claude Code/Claude Pro and any external construction skill remain replaceable worker/tool choices. Current model routing is configuration, not authority.
- No subscription state, provider token, Kilo session, chat history, model-specific transcript, or provider-specific usage record becomes product authority.
- Durable product decisions are promoted only to the active authority set:
  - [PRD](prd/SUBHFORGE-V0.2-PRD.md);
  - [Discovery](discovery/SUBHFORGE-V0.2-DISCOVERY.md) for unresolved `DI-###` items;
  - [Architecture](architecture/SUBHFORGE-V0.2-ARCHITECTURE.md);
  - [Workflow Contracts](workflow/SUBHFORGE-V0.2-WORKFLOW-CONTRACTS.md);
  - [Qualification](qualification/SUBHFORGE-V0.2-QUALIFICATION.md).
- Construction/review helpers may be removed without changing those product semantics. Obsolete Architecture Review tooling is not part of the current build workflow.
- Skills/MCP admitted for product use remain governed by the active Architecture/Discovery decisions rather than this temporary cost document.

Therefore, this document records an executable operator workflow; it does not add a SubhForge runtime component. Its pre-code role is now referenced through the Discovery pre-code closure gates rather than a separate checklist. This document should be retired after stable v0.2.0 once it is no longer needed for construction.

## Re-verification rule

Do not repeat these proofs merely to close the checklist. Re-run only the smallest affected proof when:

- authentication or provider routing is reconfigured;
- a Kilo or provider change may have altered billing, fallback, permission, or hard-stop behavior;
- the existing evidence becomes unavailable or contradicted; or
- a later release gate explicitly requires a current live canary.

Otherwise, reuse the durable evidence and preserve budget.
